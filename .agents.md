# Agent Roles and Permissions

This file defines the AI agent roles scoped for working on cmdRunner.

## cmdrunner-dev

**Role**: Core extension developer  
**Scope**: `src/**`, `test/**`, `package.json`, `tsconfig.json`, `.eslintrc.json`  
**Permissions**:
- Read and write all TypeScript source files
- Add/modify tests
- Update dependencies in package.json
- Must follow: zero `any`, no `child_process`, JSDoc on all public APIs

**Key Rules**:
1. Always read `docs/agent-knowledge-base.md` before starting
2. Run `npm run compile && npm run lint && npm test` before committing
3. Update `docs/` when changing `src/`
4. Sync `.vscode/cmdrunner.schema.json` when changing `types.ts`

---

## cmdrunner-docs

**Role**: Documentation maintainer  
**Scope**: `docs/**`, `README.md`, `CHANGELOG.md`, `.agents.md`  
**Permissions**:
- Read and write documentation files
- Update README sections
- Append to CHANGELOG

**Key Rules**:
1. Keep `docs/configuration-reference.md` in sync with `types.ts`
2. Update `docs/architecture.md` when module structure changes
3. Use Conventional Commits: `docs: description`

---

## cmdrunner-schema

**Role**: JSON schema maintainer  
**Scope**: `.vscode/cmdrunner.schema.json`, `src/types.ts`  
**Permissions**:
- Read and write `types.ts` and the JSON schema
- Must keep both files strictly in sync

**Key Rules**:
1. Every Zod schema change in `types.ts` must be reflected in `.vscode/cmdrunner.schema.json`
2. Run TypeScript compilation after any types change
3. Validate sample `.cmdrunner` files against the schema

---

## cmdrunner-release

**Role**: Release engineer  
**Scope**: `.github/workflows/**`, `CHANGELOG.md`, `package.json` (version only)  
**Permissions**:
- Manage GitHub Actions workflows
- Update CHANGELOG.md for releases
- Bump version in package.json
- Tag releases

**Key Rules**:
1. Follow semver for version bumping
2. All release entries in CHANGELOG must be complete
3. VSIX packaging must succeed before any release
4. Use Conventional Commits: `chore(release): v0.x.x`
